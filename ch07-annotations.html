Capitolo 07 · Annotations

Annotations

Le annotations sono il meta-linguaggio di CAP. Con poche righe dichiarative descrivi etichette, semantica, regole di accesso, UI generata. Padroneggiarle significa scrivere il 10% del codice e ottenere il 100% del risultato.

Annotations: il linguaggio meta di CAP

Se i tipi e le entity sono le parole di CDS, le annotations sono i suoi aggettivi. Non descrivono cosa è un dato, ma come deve essere trattato: etichetta UI, valore semantico, regola di accesso, metadato per il rendering, vincolo di capacità.

Le annotations sono dichiarative: tu scrivi cosa vuoi, CAP traduce in OData $metadata, in regole runtime, in UI generata. Lo stesso modello CDS — con le annotations giuste — produce automaticamente una List Report Fiori Elements, una Object Page editabile, un draft handling completo, regole di restrizione utente.

Il salto mentale

I framework tradizionali ti fanno scrivere codice imperativo («quando l'utente clicca, fai X»). CAP ti fa annotare il modello («questa entity ha questi campi visibili in lista»), e l'UI viene generata coerentemente. Meno codice, più consistenza.

Sintassi: prefissi, vocabolari, $value

Un'annotation ha la forma @Vocabulary.Term: value. Il vocabolario è il namespace (Common, UI, Measures, Core, Capabilities, ...); il term è il nome specifico.

tre stili equivalenti 
@Common.Label: 'Titolo libro'
@Common.Heading: 'Titolo'
title : String(100);

// stessa cosa con sintassi inline post-fissa
title : String(100) @title: 'Titolo libro';

// annotations multiple: blocco
title : String(100) @(
  Common.Label: 'Titolo',
  Common.Heading: 'Title',
  mandatory
);

Le annotations possono essere applicate a qualsiasi cosa: entity, element, association, parameter, action, service. Possono essere booleane (@readonly = true), stringhe, numeri, riferimenti a element (@Common.Text: author.name), o oggetti complessi.

varianti di valore 
// annotation booleana — sottintende true
@readonly name : String;

// annotation con riferimento a element
@Common.Text: author.name
author : Association to Authors;

// annotation oggetto complesso
@UI.HeaderInfo: {
  TypeName       : 'Book',
  TypeNamePlural : 'Books',
  Title          : { Value: title }
}

@Common: il vocabolario quotidiano

Il vocabolario @Common contiene le annotation che usi ogni giorno: etichette, intestazioni, descrizioni, semantica testuale, riferimenti.

Common.Label/Text/TextArrangement 
annotate Books with {
  ID     @Common.Label: 'ID'     @Core.Computed;
  title  @Common.Label: 'Titolo' @mandatory;
  isbn   @Common.Label: 'ISBN';
  price  @Common.Label: 'Prezzo';
  author @Common.Label: 'Autore'
         @Common.Text: author.name
         @Common.TextArrangement: #TextOnly;
};

@Common.Text è uno dei piu` potenti: dice «quando devi mostrare questo campo, usa il testo di un altro campo o di un'associazione». Combinato con @Common.TextArrangement controlli se mostrare solo il testo, solo l'id, o entrambi.

Valori di TextArrangement:

ValoreEffetto
#TextFirstNome Autore (123)
#TextLast123 (Nome Autore)
#TextOnlyNome Autore
#TextSeparate123 e Nome Autore in colonne separate
Pattern Value Help

@Common.ValueList è la chiave per generare automaticamente i value help (le finestre di selezione tipiche di Fiori) sulle association. Se la tua entity ha author : Association to Authors, basta annotare e Fiori Elements ti darà il search dialog gratis.

value help completo 
annotate Books with {
  author @Common.ValueList: {
    CollectionPath : 'Authors',
    Parameters     : [
      { $Type: 'Common.ValueListParameterInOut',
        LocalDataProperty: author_ID,
        ValueListProperty: 'ID' },
      { $Type: 'Common.ValueListParameterDisplayOnly',
        ValueListProperty: 'name' },
      { $Type: 'Common.ValueListParameterDisplayOnly',
        ValueListProperty: 'country.name' }
    ]
  };
};

@UI: generare Fiori Elements

Qui sta una delle cose più potenti di CAP: genera UI complete da annotation. Niente XML view, niente JavaScript controller. Annoti il servizio, lanci Fiori Elements, hai l'applicazione.

Le annotation @UI.* definiscono cosa mostrare (LineItem = colonne in tabella, HeaderInfo = intestazione di pagina, Facets = sezioni della Object Page) e come. Sono verbose ma estremamente espressive: una buona annotazione UI sostituisce centinaia di righe di codice frontend.

Workflow tipico

Modello dati (db/) → service (srv/) → annotations UI in un file separato (srv/catalog-ui.cds) → cds add fiori-elements oppure crea l'app a mano in app/. La separazione tra modello e annotazioni UI è un best practice fondamentale.

LineItem, HeaderInfo, Facets

Questi tre sono il core trio di una Object Page Fiori Elements:

trio UI base 
annotate CatalogService.Books with @(

  // LIST REPORT: colonne in tabella
  UI.LineItem: [
    { Value: title,         Label: 'Titolo' },
    { Value: author.name,   Label: 'Autore' },
    { Value: price,         Label: 'Prezzo' },
    { Value: stock,         Label: 'Disponibili',
      @UI.Importance: #High },
    { Value: category.name, Label: 'Categoria' }
  ],

  // OBJECT PAGE: intestazione
  UI.HeaderInfo: {
    TypeName       : 'Libro',
    TypeNamePlural : 'Libri',
    Title          : { Value: title },
    Description    : { Value: author.name }
  },

  // OBJECT PAGE: sezioni
  UI.Facets: [
    { $Type: 'UI.ReferenceFacet',
      ID    : 'GeneralInfo',
      Label : 'Informazioni generali',
      Target: '@UI.FieldGroup#General' },
    { $Type: 'UI.ReferenceFacet',
      ID    : 'Pricing',
      Label : 'Prezzo & disponibilità',
      Target: '@UI.FieldGroup#Price' },
    { $Type: 'UI.ReferenceFacet',
      ID    : 'Reviews',
      Label : 'Recensioni',
      Target: 'reviews/@UI.LineItem' }   // !! nested LineItem
  ]
);
Importance

@UI.Importance: #High dice a Fiori Elements: «mantieni questa colonna visibile anche sui dispositivi piccoli». #Low nasconde su mobile. #Medium è default.

FieldGroup, DataPoint, Identification

I FieldGroup sono gruppi logici di campi mostrati nella Object Page. I DataPoint sono singoli campi numerici con semantica di indicatore (KPI). Identification sono i campi identificativi mostrati nell'header.

FieldGroup + DataPoint 
annotate CatalogService.Books with @(

  UI.FieldGroup #General: {
    Data: [
      { Value: title },
      { Value: isbn },
      { Value: author_ID, Label: 'Autore' },
      { Value: category.name }
    ]
  },

  UI.FieldGroup #Price: {
    Data: [
      { Value: price,
        Criticality: stockStatus },             // colora in base a stockStatus
      { Value: currency.code },
      { Value: stock,
        Criticality: stockStatus },
      { Value: discount }
    ]
  },

  UI.DataPoint #StockKPI: {
    Value         : stock,
    Title         : 'Disponibilità',
    Criticality   : stockStatus,
    TargetValue   : 100,
    Visualization : #Progress
  },

  UI.HeaderFacets: [
    { $Type: 'UI.ReferenceFacet',
      Target: '@UI.DataPoint#StockKPI' }
  ]
);

I Criticality sono numeri (1=red, 2=orange, 3=green) o riferimenti a campi che producono questi valori. Fiori Elements colora automaticamente in base al loro contenuto. Bastano pochi case when per avere semafori e KPI vivi.

criticality calcolato 
// nel modello: calcoliamo lo stockStatus
entity Books as select from db.Books {
  *,
  case when stock = 0  then 1   // red
       when stock < 10 then 2   // orange
       else 3 end as stockStatus : Integer  // green
}

Filtri, ricerca, presentazione

Per controllare la List Report:

filtri e variants 
annotate CatalogService.Books with @(

  // campi nel filter bar
  UI.SelectionFields: [ title, author_ID, category_ID, price ],

  // variante: ricerca rapida
  UI.HeaderInfo: { ... },

  // search field (per @cds.search nel modello)
  UI.PresentationVariant: {
    SortOrder       : [{ Property: title, Descending: false }],
    Visualizations  : ['@UI.LineItem'],
    RequestAtLeast  : [ ID, title, price ],
    MaxItems        : 25
  },

  UI.SelectionVariant #InStock: {
    Text          : 'Solo disponibili',
    SelectOptions : [{
      PropertyName : stock,
      Ranges       : [{ Option: #GT, Low: 0 }]
    }]
  },

  UI.SelectionVariant #Expensive: {
    Text          : 'Premium',
    SelectOptions : [{
      PropertyName : price,
      Ranges       : [{ Option: #GE, Low: 50 }]
    }]
  }
);

Le SelectionVariant diventano tab preconfigurate nella List Report: un click e l'utente filtra senza scrivere nulla. Combinate con @cds.search nel modello permettono ricerche full-text immediate.

search fields 
// nel modello db/
@cds.search: { title, isbn, author.name, description }
entity Books { ... }

@Measures, @Capabilities, @Core

Tre vocabolari diversi, ognuno con un ruolo preciso:

@Measures — semantica numerica: valute, unità di misura.

Measures 
annotate Books with {
  price  @Measures.ISOCurrency: currency_code;
  weight @Measures.Unit: weightUnit;
};

Fiori Elements formatta automaticamente: 29.90 EUR, 1.5 kg.

@Capabilities — cosa può e non può fare un client.

Capabilities 
annotate CatalogService.Books with @(
  Capabilities.InsertRestrictions: { Insertable: true },
  Capabilities.UpdateRestrictions: { Updatable: true,
    NonUpdatableProperties: [ 'isbn', 'createdAt' ] },
  Capabilities.DeleteRestrictions: { Deletable: false },
  Capabilities.SearchRestrictions: { Searchable: true },
  Capabilities.FilterRestrictions: {
    RequiredProperties      : [ category_ID ],
    NonFilterableProperties : [ description ]
  }
);

@Core — metadati generici di OData: computed, immutable, descrizione.

Core 
annotate Books with {
  ID         @Core.Computed;          // non editabile, valorizzato lato server
  isbn       @Core.Immutable;         // solo al CREATE, mai update
  createdAt  @Core.Computed;
  cover      @Core.MediaType: 'image/png';
  archive    @Core.IsURL;             // renderizza come link
};

annotate Books with @Core.Description: 'Master catalog of books';

@requires e @restrict: il modello di sicurezza

CAP integra l'autorizzazione direttamente nelle annotation. Niente middleware esterni, niente decoratori imperativi: descrivi chi può cosa nel modello.

@requires 
// service-level: solo authenticated user può entrare
@(requires: 'authenticated-user')
service CatalogService { ... }

// service-level: ruoli espliciti
@(requires: [ 'admin', 'manager' ])
service AdminService { ... }

@restrict è piu` granulare e si applica a entity, azioni, function:

@restrict 
service BookshopService {

  @restrict: [
    { grant: 'READ',   to: 'authenticated-user' },
    { grant: ['CREATE','UPDATE'], to: 'editor' },
    { grant: 'DELETE', to: 'admin' }
  ]
  entity Books as projection on db.Books;

  // restriction con condizione (instance-based authorization)
  @restrict: [
    { grant: '*', to: 'admin' },
    { grant: 'READ',    to: 'user', where: 'createdBy = $user' },
    { grant: 'UPDATE',  to: 'user', where: 'createdBy = $user and status != \'approved\'' }
  ]
  entity Orders as projection on db.Orders;
}
$user, $now e attributi

$user è sempre l'utente corrente. $user.<attr> permette di leggere attributi (tenant, country, dept) dal token IAS/XSUAA. $now è il timestamp corrente. Con questi tre filtri scrivi regole tipo «l'utente vede solo i record del proprio paese e creati negli ultimi 30 giorni» in due righe.

regola istanza dinamica 
@restrict: [
  { grant: 'READ', to: 'user',
    where: 'country_code = $user.country and createdAt > $now - 30' }
]

annotate: separare modello e UI

Un'applicazione CAP matura tiene il modello dati pulito e le annotation UI in file separati. Il keyword annotate permette di aggiungere annotation a entity già definite altrove.

separation of concerns 
// db/schema.cds — solo modello, nessuna UI
entity Books {
  key ID : UUID;
  title  : String(100);
  price  : Decimal(9,2);
  author : Association to Authors;
}

// srv/catalog-service.cds — espone
service CatalogService {
  entity Books as projection on db.Books;
}

// srv/catalog-ui.cds — solo annotations UI
using CatalogService from './catalog-service';

annotate CatalogService.Books with @(
  UI.LineItem: [ ... ],
  UI.HeaderInfo: { ... },
  UI.Facets: [ ... ]
);

annotate CatalogService.Books with {
  title @title: '{i18n>BookTitle}';
  price @title: '{i18n>BookPrice}' @Measures.ISOCurrency: currency_code;
};
i18n: testi traducibili

Tutte le stringhe nell'annotation possono usare il riferimento {i18n>chiave} che punta a file _i18n/i18n.properties, _i18n/i18n_it.properties, ecc. CAP risolve il locale dell'utente automaticamente e serve l'$metadata giusto.

Esercizio del capitolo

Su un service BookshopService con entity Books, Authors, Categories, Orders:

  1. Crea un file srv/bookshop-ui.cds separato.
  2. Annota Books con UI.LineItem (almeno 5 colonne, 1 con #High), UI.HeaderInfo, UI.Facets con 3 reference facet.
  3. Crea 2 UI.FieldGroup e 1 UI.DataPoint per stock visualizzato come progress.
  4. Crea 3 UI.SelectionVariant diversi (low stock, in promozione, novità).
  5. Annota price con @Measures.ISOCurrency e @Common.Label.
  6. Crea un @Common.ValueList per il campo author.
  7. Aggiungi @restrict con 3 regole: lettura per user, scrittura per editor, delete per admin solo sui record con status = 'draft'.
  8. Imposta @Capabilities.DeleteRestrictions: { Deletable: false } sulla projection cliente, ma lascia delete attivo sulla projection admin.
Bonus expert

Sposta tutte le stringhe in _i18n/i18n.properties e crea la versione italiana _i18n/i18n_it.properties. Verifica con ?sap-language=IT nell'URL che cambino i metadati.
