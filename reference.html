CQL — quick reference

SELECT

.js
// Forma tagged template (più leggibile)
await SELECT.from`Books` where `price > 50` orderBy `title`

// Forma fluent (più componibile)
await SELECT.from(Books)
  .columns('ID', 'title', 'price')
  .where({ price: { '>': 50 } })
  .orderBy('title')
  .limit(100, 0);

// Single row (.one ritorna oggetto, non array)
const book = await SELECT.one.from(Books, { ID: bookId });

// Path expression (no JOIN scritto a mano)
await SELECT.from(Books).where({ 'author.country.code': 'IT' });

// Expand (deep read)
await SELECT.from(Books).columns(b => {
  b.'*', b.author(a => { a.name, a.country_code }), b.reviews('*')
});

// Aggregation
await SELECT.from(Books)
  .columns('author_ID', { func: 'avg', args: ['price'], as: 'avg' })
  .groupBy('author_ID')
  .having({ avg: { '>': 20 } });

INSERT / UPDATE / UPSERT / DELETE

.js
// INSERT singolo
await INSERT.into(Books).entries({ ID: cuid(), title: 'X', price: 10 });

// INSERT bulk
await INSERT.into(Books).entries([{ ... }, { ... }, { ... }]);

// UPDATE
await UPDATE(Books).set({ price: 15 }).where({ ID: bookId });

// UPDATE con espressione
await UPDATE(Books, bookId).set({ stock: { '-=': 1 } });

// UPSERT (insert se non esiste, update altrimenti)
await UPSERT.into(Books).entries({ ID: bookId, title: 'X' });

// DELETE
await DELETE.from(Books).where({ ID: bookId });
await DELETE.from(Books, bookId);  // shortcut su key

Gotcha & best practice

⚠ Naming

Le entity tipicamente al plurale (Books), gli aspect e i type al singolare (Address). I service nel formato PascalCase con suffix -Service.

⚠ UUID

Sempre cuid per le entity transazionali. Per code list usa String(n) come key (più leggibile, indicizzabile, fixed-length).

⚠ Path expression

Mai scrivere JOIN a mano in CQL. Usa .where('author.country.code', 'IT'): CAP genera il JOIN ottimale e lo pusha a HANA.

⚠ Composition vs Association

Composition = padre possiede i figli (cascade delete, deep create). Association = puntatore (i record vivono di vita propria).

⚠ Draft validation

Validation strict in before('CREATE'/'UPDATE') sull'entity. Validation soft (formato, range) in before('PATCH', Entity.drafts). Non confondere.

⚠ N+1

Mai un loop con SELECT dentro. Sempre columns(b => b.author('*')) per fare expand. Una sola query, JOIN al DB.

⚠ localized

Quando leggi una entity localized usa SELECT.from(localized.Books) per ottenere la traduzione automatica nella lingua dell'utente.

⚠ Tx esplicite

Per logica multi-step usa cds.tx. Default: tutto in autocommit. Se vuoi rollback su errore di un step, devi avvolgere in transaction.

⚠ @restrict

Restrict supporta where con SQL: where: 'owner = $user'. Magic vars: $user, $user.id, $now, $user.locale, $user.<attribute>.

⚠ HDI deploy

Su HANA Cloud i deploy avvengono via HDI container. cds deploy in locale, cf deploy con mta.yaml in BTP. Mai mischiarli.

⚠ Annotations syntax

L'array di annotation accetta sia stringhe semplici sia oggetti. Per UI.LineItem usa sempre oggetti: { Value: title, Label: 'Title' }.

⚠ Side effects

Quando un campo dipende da un altro server-side, dichiara @Common.SideEffects.TargetProperties così il client ricarica al cambiamento.
