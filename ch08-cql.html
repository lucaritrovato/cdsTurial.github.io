Capitolo 08 · CQL & CQN

CQL & CQN

CQL è il linguaggio di query di CAP. Sembra SQL ma porta a un livello superiore: path expressions, expand, aggregazioni dichiarative, tagged templates con sicurezza built-in. Padroneggiarlo significa scrivere database logic con un decimo del codice.

CQL: SQL ridisegnato per il XXI secolo

CQL (Core Query Language) è il linguaggio di query di CAP. Sembra SQL, ma non è SQL. È una versione semplificata, regolarizzata, orientata agli oggetti: tratta le association come prime classi, supporta path expressions ovunque, ha sintassi piu` moderne per le aggregazioni e le proiezioni.

In Node.js scrivi CQL con due stili: fluent API (catena di metodi) o tagged templates (SQL-like). Entrambi producono lo stesso oggetto canonico: CQN (Core Query Notation).

due stili, una semantica 
// FLUENT API
const books = await SELECT.from(Books)
  .columns('ID', 'title', 'price')
  .where({ price: { '>': 20 } })
  .orderBy('title')
  .limit(10);

// TAGGED TEMPLATE
const books = await SELECT`from ${Books} { ID, title, price } where price > ${20} order by title limit ${10}`;

CQN: il formato canonico delle query

Tutte le query CQL, prima di essere eseguite, vengono convertite in CQN: un oggetto JavaScript JSON-serializzabile. CQN è il linguaggio intermedio di CAP: viaggia su rete, si salva in cache, si trasforma con strumenti tipo Pipeline.

CQN puro 
// la query precedente, in CQN puro
{
  SELECT: {
    from: { ref: ['my.bookshop.Books'] },
    columns: [
      { ref: ['ID'] },
      { ref: ['title'] },
      { ref: ['price'] }
    ],
    where: [{ ref: ['price'] }, '>', { val: 20 }],
    orderBy: [{ ref: ['title'] }],
    limit: { rows: { val: 10 } }
  }
}
Perché importa

Conoscere CQN ti permette di manipolare le query a runtime: aggiungere filtri di sicurezza, riscrivere condizioni, intercettare e ottimizzare. Negli handler req.query è sempre un oggetto CQN: puoi leggerlo, modificarlo, sostituirlo.

manipolazione CQN 
// intercetta una READ e aggiungi un filtro di sicurezza
this.before('READ', Orders, req => {
  // req.query è un oggetto CQN: aggiungi un AND
  req.query.SELECT.where = [
    ...(req.query.SELECT.where || []),
    'and',
    { ref: ['createdBy'] }, '=', { val: req.user.id }
  ];
});

SELECT: la query base

varianti di SELECT 
// tutti i libri
const all = await SELECT.from(Books);

// uno solo (per key)
const one = await SELECT.one.from(Books).where({ ID: bookId });

// colonne specifiche
const light = await SELECT.from(Books).columns('ID', 'title');

// con calcoli
const withVat = await SELECT.from(Books).columns(b => {
  b.ID,
  b.title,
  b.price.as('net'),
  (b.price * 1.22).as('gross')
});

// con ordinamento e paginazione
const page = await SELECT.from(Books)
  .orderBy({ title: 'asc' }, { price: 'desc' })
  .limit(10, 20);  // 10 righe, offset 20

// distinct
const countries = await SELECT.distinct.from(Authors).columns('country_code');
SELECT.one

SELECT.one restituisce un singolo oggetto (o null), non un array. È ottimo per le query «trovami questo record specifico»: niente [0] da gestire, niente confusione.

Path expressions: addio JOIN scritti a mano

La superpotenza di CQL: scrivi book.author.country.name e CAP genera i JOIN necessari. Non scriverai mai più un JOIN a mano.

path expressions 
// trova tutti i libri di autori italiani
const books = await SELECT.from(Books)
  .where({ 'author.country.code': 'IT' });

// stesso con tagged template
const books = await SELECT`
  from ${Books}
  where author.country.code = ${'IT'}
`;

// nei columns: estrai dati lungo il path
const rows = await SELECT.from(Books).columns(
  'ID',
  'title',
  'author.name as authorName',
  'author.country.name as country',
  'publisher.country.region.name as region'
);

Sotto il cofano, CAP traduce in SQL con i JOIN giusti. Se attraversi un'association to-many, ottieni una riga per ogni combinazione (cartesiano), come in SQL.

SQL generato 
-- l'SQL che CAP produce dietro le quinte
SELECT b.ID, b.title,
       a.name AS authorName,
       c.name AS country
FROM Books b
LEFT JOIN Authors a   ON b.author_ID = a.ID
LEFT JOIN Countries c ON a.country_code = c.code
WHERE c.code = 'IT';

Expand: la chiave dei deep read

Path expressions ti danno colonne piatte. Expand ti dà oggetti annidati: una query che restituisce il libro con dentro l'oggetto autore e l'array delle recensioni. È il modo idiomatico per popolare strutture gerarchiche complete.

expand multi-level 
// expand semplice: porta dentro l'autore intero
const book = await SELECT.one.from(Books).columns(b => {
  b.'*',
  b.author(a => { a.ID, a.name, a.country_code })
}).where({ ID: bookId });

// risultato
{
  ID: 'a1b2-...',
  title: 'Domain-Driven Design',
  price: 45,
  author: { ID: 'x9y8-...', name: 'Eric Evans', country_code: 'US' }
}

// expand to-many: array di figli
const book = await SELECT.one.from(Books).columns(b => {
  b.'*',
  b.reviews(r => { r.ID, r.rating, r.comment })
}).where({ ID: bookId });

// risultato
{
  ID: 'a1b2-...',
  title: 'Domain-Driven Design',
  reviews: [
    { ID: 'r1-...', rating: 5, comment: 'Excellent' },
    { ID: 'r2-...', rating: 4, comment: 'Hard but worth it' }
  ]
}

// expand annidato: tre livelli
const book = await SELECT.one.from(Books).columns(b => {
  b.ID, b.title,
  b.author(a => {
    a.name,
    a.country(c => { c.code, c.name })
  }),
  b.reviews(r => { r.rating, r.user(u => { u.name }) })
});
Con tagged template

L'expand ha sintassi naturale anche in template: { author { name, country { code, name } } }. La curly brace dopo un'association vale come expand.

expand in template 
const book = await SELECT.one`
  from ${Books} {
    ID, title,
    author { name, country { code, name } },
    reviews { rating, comment }
  }
  where ID = ${bookId}
`;

WHERE, filter, e operatori speciali

where avanzato 
// notazione oggetto: comodissima per filtri AND
SELECT.from(Books).where({
  stock: { '>': 0 },
  price: { between: [10, 100] },
  title: { like: '%CAP%' }
});

// operatori supportati
{ price: { '=':  29 } }
{ price: { '!=': 29 } }
{ price: { '>=': 10 } }
{ price: { '<':  100 } }
{ price: { between: [10, 100] } }
{ title: { like: '%cap%' } }
{ ID:    { in: ['a1', 'a2', 'a3'] } }
{ description: { isNull: true } }

// IN con subquery
SELECT.from(Books).where({
  author_ID: {
    in: SELECT.from(Authors).columns('ID').where({ country_code: 'IT' })
  }
});

// OR / AND espliciti con array
SELECT.from(Books).where([
  { author_ID: 'a1' },
  'or',
  { author_ID: 'a2' }
]);
Trap: shorthand vs operatori

.where({ price: 29 }) è price = 29. .where({ price: [29, 30] }) è price IN (29, 30). .where({ price: { between: [29, 30] } }) è price BETWEEN 29 AND 30. Tre comportamenti diversi: leggi sempre attentamente.

Aggregazioni e GROUP BY

GROUP BY 
// totali per autore
const stats = await SELECT.from(Books)
  .columns(
    'author_ID',
    { func: 'count', args: [{ ref: ['*'] }], as: 'cnt' },
    { func: 'avg',   args: [{ ref: ['price'] }], as: 'avgPrice' },
    { func: 'sum',   args: [{ ref: ['stock'] }], as: 'totalStock' }
  )
  .groupBy('author_ID')
  .having({ 'sum(stock)': { '>': 100 } })
  .orderBy({ cnt: 'desc' });

// versione tagged template (molto piu` leggibile)
const stats = await SELECT`
  from ${Books} {
    author_ID,
    count(*)    as cnt   : Integer,
    avg(price)  as avgP  : Decimal(9,2),
    sum(stock)  as totS  : Integer
  }
  group by author_ID
  having sum(stock) > 100
  order by cnt desc
`;
Pushdown

Le aggregazioni in CDS vengono pushed down al database: HANA esegue il calcolo, CAP riceve già i risultati aggregati. Non c'è mai un caricamento in memoria di milioni di righe. Per analisi pesanti, valuta calculation view nativi (capitolo 9).

INSERT, UPDATE, UPSERT, DELETE

mutazioni 
// INSERT singolo
await INSERT.into(Books).entries({
  title: 'Refactoring',
  price: 35,
  author_ID: 'a1b2-...'
});

// INSERT multipli (bulk)
await INSERT.into(Books).entries([
  { title: 'Clean Code', price: 30, author_ID: 'a1' },
  { title: 'The Pragmatic Programmer', price: 28, author_ID: 'a2' }
]);

// INSERT da SELECT (clone)
await INSERT.into(BooksArchive)
  .columns('ID', 'title', 'price')
  .as(SELECT.from(Books).columns('ID', 'title', 'price').where({ archived: true }));

// UPDATE
await UPDATE(Books)
  .set({ price: { '+=': 5 } })       // aritmetica incrementale!
  .where({ category_code: 'BUSINESS' });

// UPSERT: inserisci o aggiorna se la key esiste
await UPSERT.into(Books).entries({
  ID: 'a1b2-...',
  title: 'New title',
  price: 42
});

// DELETE
const { affectedRows } = await DELETE.from(Books).where({ stock: 0 });
console.log(`${affectedRows} libri eliminati`);

// DELETE deep (con composition): elimina anche figli
await DELETE.from(Orders).where({ ID: orderId });
// CAP elimina automaticamente le composition (es. OrderItems)
Aritmetica incrementale

{ '+=': 5 }, { '-=': 1 }, { '*=': 2 }: utilissimi per stock, contatori, saldi. Generano SQL atomico SET stock = stock - 1, evitando race condition tra read e update.

Tagged templates: la sintassi naturale

I tagged templates leggono come SQL ma con i poteri di CQL. Le interpolazioni ${...} sono parametrizzate: niente SQL injection, niente concatenazione manuale.

stesso risultato, due stili 
const minPrice = 20;
const country  = 'IT';

const books = await SELECT`
  from ${Books} {
    ID,
    title,
    price,
    author.name as authorName,
    author.country.name as country,
    reviews { rating, comment }
  }
  where price > ${minPrice}
    and author.country.code = ${country}
  order by title
  limit 20
`;

// equivalente fluent
const books = await SELECT.from(Books)
  .columns(b => { b.ID, b.title, b.price,
    b.author(a => { a.name.as('authorName'),
                   a.country(c => c.name.as('country')) }),
    b.reviews(r => { r.rating, r.comment }) })
  .where({ price: { '>': minPrice }, 'author.country.code': country })
  .orderBy('title')
  .limit(20);
Quando preferire uno o l'altro

Tagged template per query lunghe, leggibili, con expand annidati. Fluent quando devi costruire dinamicamente la query (parti opzionali, filtri condizionali, append). Le due forme si possono mescolare via cqn4sql.

Transazioni e cds.tx

Ogni richiesta HTTP in CAP è già dentro una transazione automatica. Ma quando devi fare operazioni fuori dal flusso request/response (job, background, batch), gestisci tu la transazione con cds.tx.

transactions 
// transazione esplicita
await cds.tx(async tx => {
  await tx.run(INSERT.into(Orders).entries({ ... }));
  await tx.run(UPDATE(Books).set({ stock: { '-=': 1 } }).where({ ID: bookId }));
  // se una delle due fallisce: rollback automatico
});

// dentro un handler: usa req invece di tx
this.on('submitOrder', async req => {
  const { book, quantity } = req.data;

  // req.run() è la transazione corrente (quella della richiesta HTTP)
  await req.run(UPDATE(Books).set({ stock: { '-=': quantity } }).where({ ID: book }));
  return req.run(INSERT.into(Orders).entries({ book_ID: book, quantity }));
});

// rollback manuale (caso particolare)
await cds.tx(async tx => {
  try {
    await tx.run(INSERT.into(...).entries(...));
    if (somethingWrong()) throw new Error('rollback');
  } catch (e) {
    // tx.rollback() implicito quando esce con throw
    throw e;
  }
});
Mai mescolare connessioni

Non eseguire query con cds.db dentro un cds.tx: useresti due connessioni diverse e perderesti l'atomicità. Dentro la transazione, usa solo il parametro tx.

Cross-service queries con cds.connect.to

I servizi CAP comunicano tra loro come fossero database. cds.connect.to('NomeServizio') ti dà un client su cui chiamare CQL. Funziona sia per servizi locali sia per servizi remoti (S/4HANA, SuccessFactors, qualunque OData esterno configurato come destination).

connect.to multi-uso 
// chiamata a un altro servizio CAP nella stessa app
const catalog = await cds.connect.to('CatalogService');
const top = await catalog.run(
  SELECT.from('Books').orderBy({ rating: 'desc' }).limit(10)
);

// chiamata a servizio esterno (configurato in package.json o env)
const s4 = await cds.connect.to('API_BUSINESS_PARTNER');
const partners = await s4.run(
  SELECT.from('A_BusinessPartner').where({ Country: 'IT' }).limit(50)
);

// emettere eventi su una coda
const messaging = await cds.connect.to('messaging');
await messaging.emit('OrderPlaced', { orderId, total });

// chiamata REST generica
const api = await cds.connect.to('ExternalAPI');
const data = await api.send({
  method: 'POST',
  path  : '/v2/calculate',
  data  : { amount: 100 }
});
wiring servizi esterni 
# package.json — configurazione destination
"cds": {
  "requires": {
    "API_BUSINESS_PARTNER": {
      "kind": "odata-v2",
      "model": "srv/external/API_BUSINESS_PARTNER",
      "credentials": { "destination": "S4HANA_CLOUD" }
    },
    "messaging": {
      "kind": "enterprise-messaging"
    }
  }
}

Esercizio del capitolo

  1. Scrivi una query CQL (fluent + tagged) che restituisca tutti i libri con autore italiano, prezzo > 20, con expand di author e reviews.
  2. Scrivi un'aggregazione che dia: per ogni categoria, count, avg(price), max(price), sum(stock); filtra solo categorie con almeno 5 libri.
  3. Scrivi una UPDATE che incrementi del 10% i prezzi dei libri di una specifica categoria.
  4. Scrivi un'UPSERT che inserisca o aggiorni 5 libri in batch.
  5. In un handler this.on('placeOrder', ...), dentro cds.tx: decrementa stock, inserisci Order, inserisci OrderItems, emetti evento 'OrderPlaced'.
  6. Connettiti a un servizio esterno fake (mock) 'CurrencyService' e moltiplica il prezzo dei libri per il tasso di cambio prima di restituirli.
  7. Crea una query con IN subquery: tutti i libri di autori che hanno almeno 3 recensioni con rating >= 4.
